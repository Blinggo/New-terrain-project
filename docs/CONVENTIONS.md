# Conventions - VoxelTerrain M00

These conventions are enforced by tooling wherever possible. A convention that no script
checks is a wish, not a convention.

## 1. Language and files

- GDScript only. One `class_name` per file, file name = snake_case of the class name
  (`hash64.gd` -> `Hash64`). Scripts without a class are lowercase verbs
  (`run_tests.gd`, `capture_screenshots.gd`).
- `tools/check_scripts.sh` compile-checks every `.gd` under `src/`, `tests/`, `tools/`
  with warnings treated as errors. **Zero warnings is a build gate**, not an aspiration:
  Variant-inference warnings are errors here on purpose, because silently-Variant locals
  are how determinism-relevant typos survive.
- After adding a `class_name`, run `godot --headless --path . --import` or the class will
  not resolve in other scripts (`.godot/global_script_class_cache.cfg`).

## 2. Layering (see docs/adr/ADR-0002)

Dependency direction: runtime -> adapters -> (core, worldgen, spine). Core depends on
nothing project-internal.

- **Only `src/adapters/` may reference Voxel Tools classes.** Everything above the adapter
  boundary sees `Node3D`, `Resource`, `Vector3i`, `Dictionary`.
- `src/runtime/debug/` and `src/runtime/world/` may use `Time.*` and wall-clock (HUD
  timing, screenshot names, the F5 debug seed). `src/worldgen/`, `src/adapters/`,
  `src/core/` may not - `tests/determinism/test_determinism.gd` D5 lints exactly those
  three folders for `randf(`, `randi(`, `Time.get_`, `randomize(` and fails on a hit.
- `src/spine/` and `src/worldgen/` are **empty in M00 on purpose**; D5b fails if they are
  not, so no later-milestone code can sneak into M00.
- Helpers inside a `Control`/`Node` subclass are prefixed `_`: Godot 4.7 `Control` already
  declares `get_parent_area_size()`, and shadowing a native method is a warning-as-error.

## 3. Determinism (see docs/adr/ADR-0003)

- Never `randf()`, `randi()`, `randomize()`, `Time.*` in generation code. Never depend on
  frame count, node order, dictionary iteration order or player position.
- All randomness from one explicit integer seed in `content/world_config.json`.
- Golden hashes use `Hash64` (FNV-1a 64), never Godot `hash()`.
- Fixed iteration everywhere a hash is produced: `ChunkOrigins` returns the same 64
  origins in the same order on every run and every machine.
- Anything that must be reproducible is derived by arithmetic or `Hash64`, including the
  placeholder atlas pixels and the benchmark chunk grid.

## 4. Data over editor artifacts

- Blocks live in `content/blocks/blocks.json`; the library is built in code by
  `BlockLibraryBuilder`. **No hand-authored `.tres` library, ever.** Adding a block is a
  JSON edit plus, at most, atlas tiles.
- World shape lives in `content/world_config.json`, validated on load by
  `WorldConfig._validate()`; validation errors abort the boot, warnings are printed.
- The atlas is generated by `tools/generate_placeholder_atlas.gd`; its sha256 is pinned in
  `tests/smoke/test_assets.gd` S3d so "the art changed by accident" is a test failure.

## 5. Testing and reporting

- Every check returns `{suite, id, status, message, evidence}`. Evidence is mandatory: a
  PASS without the numbers that justify it is not acceptable in this project.
- Statuses: `PASS`, `FAIL`, `BLOCKED`. **BLOCKED means "a human/window/device must do
  this", and is not a failure** - but it must say exactly what is missing and how to run
  it. Never mark something BLOCKED to hide a failure, never PASS something not run.
- A module that produces zero results is a FAIL (the harness enforces this); a runner that
  cannot load a module prints the parse error and exits 1. Silent green is the one
  unacceptable outcome.
- Perf numbers always carry their hardware (`B0`/`R1` record OS, CPU, RAM, GPU, renderer,
  and BLOCK themselves as device claims when the machine is weaker than the Android
  target - which the CI box always is).
- Screenshots come only from the running game via `tools/capture_screenshots.gd`, which
  refuses to run headless and waits for the world to be loaded *and meshed and stable*
  before each shot.

## 6. Naming and units

- 1 block = 1 metre, always. Y from -64 (inclusive) to 320 (exclusive); sea level 64.
- `view_distance_chunks` is the config unit; the engine's `VoxelViewer.view_distance` is
  in **voxels** (measured, `tools/probe_streaming.gd`), converted by
  `TerrainAdapter.apply_view_distance()`.
- Sizes in reports: MiB with one decimal; frame times in ms with two; per-chunk costs in
  ms with four.

## 7. Commits and vendored code

- `addons/zylann.voxel/` is vendored and frozen: `docs/reports/addon_manifest.json`
  (sha256 of all 35 files) is the baseline and `S2i` re-checks it on every run.
- Generated evidence files are committed on purpose: `voxel_api_dump.json`,
  `voxel_graph_nodes.json`, `golden_hashes.json`, `addon_manifest.json`,
  `test_results.json`, `docs/reports/screenshots/*.png`. They are the audit trail.
